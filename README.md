# Titanic-ML

Учебное исследование Titanic. Выберите нужный ноутбук:

| Ноутбук | Что посмотреть |
|---|---|
| [EDA](notebooks/EDA.ipynb) | Данные, пропуски, связи, необычные значения и решения по обработке |
| [Modeling](notebooks/modeling.ipynb) | История классических моделей, бустингов и Feature Engineering |
| [Model stability](notebooks/model_stability.ipynb) | Сравнение выбранных моделей на разбиениях с seeds 42, 17 и 123 |
| [DNN](notebooks/dnn.ipynb) | Текущий запуск нейросети, история экспериментов и итоговая внешняя CV |
| [Ensembles](notebooks/ensembles.ipynb) | OOF, усреднение, голосование, stacking и проверка устойчивости |

В modeling запуск всех ячеек повторяет дорогие сетки. Для чтения сохранённых результатов разных seed используйте инструкции в начале model_stability; повторное обучение не требуется.

## Запуск

Python 3.11 или новее. Установка из requirements и запуск проверены в чистом окружении Windows, Python 3.11.3, CPU. Из корня проекта (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 main.py
```

Исходные CSV включены в репозиторий: `data/train.csv` и `data/test.csv`. Скрипт выполняет CV, обучает Pipeline на всём train и сохраняет `metrics.json` и `submission.csv` в папку из `output_dir`. Повторный запуск заменяет эти файлы.

`config.yaml` содержит пути, target, исключаемые колонки, seed, CV, признаки и обработку в `preprocessing`, модель с параметрами. Другой конфиг: `main.py --config path/to/config.yaml`. Смена названия модели не воспроизводит автоматически её лучшие признаки, обработку и параметры из исследований; их нужно согласовать отдельно.

По умолчанию запускается выбранный Random Forest: 200 деревьев, `min_samples_leaf=4`, `min_samples_split=10`, `max_features=None`, без ограничения глубины. CV на пяти стратифицированных фолдах seed 42: **Accuracy 84.62% ± 2.11 п.п., ROC-AUC 0.88109**. На других разбиениях результат меняется; уверенное превосходство над XGBoost не установлено.

[RESEARCH_SUMMARY.md](RESEARCH_SUMMARY.md) — краткие итоги исследований: проверенные идеи, выбранные решения и ограничения оценки.

## Как экспериментировать

Локальный `docs/ML_WORKFLOW.md` — шпаргалка: загрузка → признаки → обработка колонок → Pipeline → CV → итоговое обучение. Используем обычный pandas и sklearn; собственного Runner больше нет.

- Признаки, дополнительные преобразования и масштабирование задаются в `preprocessing` конфига; main использует те же функции, что классические исследования.
- Модель и параметры скрипта меняйте в `config.yaml`.
- В выбранном RF семь исходных признаков: `Pclass` числовой, `Sex` бинарный one-hot, `Embarked` one-hot; числа заполняются медианой, масштабирование выключено. Для KNN и линейных моделей настройте их выбранную обработку отдельно.

Доступные модели: `decision_tree`, `random_forest`, `logistic_regression`, `knn`, `catboost`, `lightgbm`, `xgboost`. Скрипт использует общую обработку для всех моделей; native-категории здесь не подключены. Метрики рассчитаны для бинарной классификации.

Переиспользуемый код:

- [src/preprocessing.py](src/preprocessing.py) — `prepare_features` создаёт признаки Titanic, `build_preprocessor` собирает sklearn-преобразования по спискам колонок.
- [src/sklearn_experiments.py](src/sklearn_experiments.py) — сборка pipeline, CV, подбор параметров и журналы. Старые импорты предобработки из этого модуля сохранены.
- [src/config.py](src/config.py) — загрузка YAML и создание модели.
- [src/dnn_training.py](src/dnn_training.py) — создание MLP/EmbeddingMLP, обучение, оценка и предсказания.

Общие imputer/scaler/encoder можно использовать для других табличных данных; правила `FamilySize`, `SexPclass` и другие признаки относятся к Titanic. Main использует этот модуль; DNN сохраняет собственную подготовку тензоров. Результаты `experiments/runs/` исключены из Git.

## Бустинги

CatBoost, LightGBM и XGBoost исследованы в [modeling.ipynb](notebooks/modeling.ipynb). CatBoost получает категории напрямую и использует `Pool/cv`; LightGBM проверен с one-hot и встроенными категориями; XGBoost — с pipeline и one-hot. Интерфейс sklearn не отключает встроенные возможности библиотек. Различия в обработке и способе CV указаны в [журнале](RESEARCH_SUMMARY.md).

## Структура проекта

- `notebooks/` — EDA, история моделей, проверка разбиений, DNN и ансамбли; каждый ноутбук содержит инструкции запуска и выводы.
- `src/` — загрузка конфига и переиспользуемый код обучения и экспериментов.
- `scripts/` — [проверка двух DNN на пяти фолдах](scripts/dnn_cv.py).
- `data/` — исходные CSV; `experiments/` — журналы, оценки CV и предсказания.
- `docs/` — локальные учебные заметки и чеклист; папка исключена из Git и отсутствует после клонирования.
- `tests/` — существующие технические проверки DNN.

Ноутбуки можно открывать из корня проекта или из `notebooks/`: первая ячейка настраивает импорты и рабочую папку. Все пути в `config.yaml` остаются относительно корня проекта.

Повторить 10 обучений CV из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/dnn_cv.py
```

Результаты записываются в `experiments/dnn_cv_*.csv` и `experiments/dnn_cv_*.json`; основной журнал `experiments/dnn_results.csv` не изменяется.

## Устройство для DNN

В `config.yaml` настройка `dnn.device` действует для DNN-ноутбука и CV-скрипта:

- `cpu` — обучение на процессоре (текущее значение).
- `cuda` — обучение на совместимой NVIDIA GPU; при недоступной CUDA запуск остановится с пояснением.
- `auto` — CUDA, если доступна, иначе CPU.

Dataset хранится на CPU, батчи переносятся на устройство модели. `predict` возвращает логиты на CPU; журнал сохраняет фактическое устройство. После изменения конфига перезапустите ячейки с его загрузкой и созданием модели. По умолчанию requirements устанавливает `torch==2.14.1+cpu` из официального CPU-источника `https://download.pytorch.org/whl/cpu` вместе с остальными зависимостями одной командой, указанной выше.

Для GPU замените CPU-пакет совместимой CUDA-сборкой по [официальной инструкции PyTorch](https://pytorch.org/get-started/locally/), затем выберите `cuda` или `auto`. Для повторной установки окружения с GPU также замените CPU-фиксацию в requirements: она иначе вернёт CPU-сборку. `dnn.device` выбирает устройство, но не устанавливает CUDA-поддержку. Текущая проверенная установка — CPU; GPU здесь не проверялась.
