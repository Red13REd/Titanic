# Titanic-ML

Учебное сравнение моделей: [EDA](notebooks/EDA.ipynb) — анализ данных, [modeling](notebooks/modeling.ipynb) — эксперименты, [DNN](notebooks/dnn.ipynb) — нейросети и итоговые выводы.

## Запуск

Из корня проекта (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 main.py
```

CSV должны лежать в `data/train.csv` и `data/test.csv`. Скрипт выполняет CV, обучает Pipeline на всём train и сохраняет `metrics.json` и `submission.csv` в папку из `output_dir`. Повторный запуск заменяет эти файлы.

`config.yaml` содержит пути, target, исключаемые колонки, seed, CV и модель с параметрами. Другой конфиг: `main.py --config path/to/config.yaml`.

Сейчас выбрано дерево глубины 5: CV Accuracy **0.8126 ± 0.0138**. Это простой вариант для запуска, а не лучшая найденная модель. Лучший сохранённый лес дал **0.8462 ± 0.0211**. Наборы признаков, обработка и иногда фолды различались: таблица в журнале не является строгим рейтингом алгоритмов.

[KaggleTemplate.md](KaggleTemplate.md) — общий журнал моделей, экспериментов и выводов, включая DNN.

## Как экспериментировать

Локальный `docs/ML_WORKFLOW.md` — шпаргалка: загрузка → признаки → обработка колонок → Pipeline → CV → итоговое обучение. Используем обычный pandas и sklearn; собственного Runner больше нет.

- Колонки и обработку меняйте в ноутбуке; выбранный вариант перенесите в `main.py`.
- Модель и параметры скрипта меняйте в `config.yaml`.
- В `main.py` используются семь исходных признаков, медианы и one-hot, без scaling. Для KNN и линейных моделей scaling можно добавить числовым колонкам.

Доступные модели: `decision_tree`, `random_forest`, `logistic_regression`, `knn`, `catboost`, `lightgbm`, `xgboost`. Скрипт использует общую обработку для всех моделей; native-категории здесь не подключены. Метрики рассчитаны для бинарной классификации.

В `src/config.py` остались загрузчик общего YAML и выбор модели. Старый `src/sklearn_experiments.py` сохранён для существующих разделов ноутбука. Результаты `experiments/runs/` исключены из Git.

## Нативные бустинги без sklearn

Описание отдельного эксперимента `boosting.ipynb` (файл отсутствует в текущем рабочем дереве): CatBoost Pool/cv, LightGBM Dataset/cv/train и XGBoost DMatrix/cv/train. Без sklearn Pipeline, one-hot, scaling и заполнения числовых NaN. Все модели используют одинаковые стратифицированные фолды. Ноутбук сравнивает Accuracy и AUC, выбирает число итераций и сохраняет модель с submission в `experiments/runs/native_boosting/<model>/`. Категориальные пропуски CatBoost заменяются строкой; для LightGBM/XGBoost используются pandas category и единый словарь train/test. CV участвует в подборе числа итераций: это не независимая итоговая оценка.

## Структура проекта

- `notebooks/` — EDA, классические модели и [DNN](notebooks/dnn.ipynb), включая результаты и выводы.
- `src/` — загрузка конфига и переиспользуемый код обучения и экспериментов.
- `scripts/` — [проверка двух DNN на пяти фолдах](scripts/dnn_cv.py).
- `data/` — исходные CSV; `experiments/` — журналы, оценки CV и предсказания.
- `docs/` — локальные учебные заметки и чеклист; папка исключена из Git и отсутствует после клонирования.
- `tests/` — существующие технические проверки DNN.

Ноутбуки можно открывать из корня проекта или из `notebooks/`: первая ячейка настраивает импорты и рабочую папку. Все пути в `config.yaml` остаются относительно корня проекта.

Повторить 10 обучений CV из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/dnn_cv.py
```

Результаты записываются в `experiments/dnn_cv_*.csv` и `experiments/dnn_cv_*.json`; основной журнал `experiments/dnn_results.csv` не изменяется.

## Устройство для DNN

В `config.yaml` настройка `dnn.device` действует для DNN-ноутбука и CV-скрипта:

- `cpu` — обучение на процессоре (текущее значение).
- `cuda` — обучение на совместимой NVIDIA GPU; при недоступной CUDA запуск остановится с пояснением.
- `auto` — CUDA, если доступна, иначе CPU.

Dataset хранится на CPU, батчи переносятся на устройство модели. `predict` возвращает логиты на CPU; журнал сохраняет фактическое устройство. После изменения конфига перезапустите ячейки с его загрузкой и созданием модели. В текущем окружении установлена сборка PyTorch `+cpu`; для CUDA потребуется соответствующая сборка PyTorch.
